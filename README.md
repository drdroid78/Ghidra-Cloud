# Ghidra Cloud

Облачная Ghidra 12.2 Headless на бесплатных стандартных исполнителях публичного GitHub Actions. Официальный архив проверяется закреплённым SHA-256. JDK 25. Исследуемый код не запускается.

## Запуск

[Actions → Ghidra Cloud → Run workflow](https://github.com/drdroid78/Ghidra-Cloud/actions/workflows/ghidra-cloud.yml).

| Режим | Параметры |
|---|---|
| selftest | Контрольные ELF x86-64, ARM32, ARM64 без символов, RAW BIN, сравнение и восстановление проекта |
| analyze | binary_path — путь к разрешённому публичному бинарному файлу |
| compare | binary_path и compare_path — два бинарных файла |
| resume | resume_run — ID успешного запуска, resume_label — имя проекта (a, b, raw, arm32, arm64, indirect, large) |

Дополнительные параметры: function_filter (часть имени/адреса, * — все), query (буквальная подстрока без учёта регистра), max_functions (1–5000 попыток декомпиляции, по умолчанию 200).

RAW BIN: явно задайте raw_language (например x86:LE:64:default), raw_base и raw_entry (шестнадцатеричные адреса), raw_compiler (например gcc). При пустом raw_language используется автоматический загрузчик. Для сравнения RAW обоим файлам задаются одинаковые параметры. Неверная архитектура, адрес или режим процессора приведут к неверному анализу; универсального автоопределения RAW нет. Адрес загрузки блока не обязательно равен IMAGE_BASE программы; для RAW сохраняются входные параметры в raw-import.json, а адрес функции проверяется по functions.tsv.

## Результаты

В артефакте ghidra-report:
- summary.txt — архитектура, базовый адрес, охват, счётчики ошибок и ограничений.
- functions.tsv — адреса, имена, размеры тел и SHA-256 байтов инструкций.
- decompiled.txt — псевдокод.
- strings.tsv, ascii-offsets.txt, utf16le-offsets.txt — определённые строки и сырые строки с файловыми смещениями.
- constants.tsv — скалярные операнды (hex и unsigned decimal).
- xrefs.tsv — перекрёстные ссылки с функциями-источниками и целями.
- calls.tsv — рёбра графа вызовов, включая помеченные косвенные/неразрешённые вызовы.
- matches.tsv — совпадения по запросу в проанализированных данных.
- analysis.log и headless-console.log — журналы; input.sha256 и input-format.txt — идентификация.
- comparison/ — интервалы отличающихся файловых смещений, сравнение отпечатков функций и сводка.

Артефакт ghidra-project содержит сохранённые проекты Ghidra. Режим compare также запускает штатный Auto Version Tracking Ghidra и сохраняет сессию CloudVT (оба бинарника в одном проекте a), экспорт version-tracking.tsv с ассоциациями, статусами, similarity/confidence и журналами. Исходные файлы не изменяются; штатный AutoVT может переносить разметку в проект назначения, а не в бинарник. Режим resume восстанавливает проект из предыдущего успешного запуска и выполняет новый поиск/экспорт без полного повторного анализа. Артефакты хранятся 14 дней; скачайте их, если нужна долговременная копия.

## Границы

- Публичные файлы и результаты. Не публикуйте приватные прошивки, токены, материалы без права распространения.
- Каждый входной файл до 100 МиБ. Анализ ограничен 60 минутами на задание, автоанализ — 20 минутами на файл, декомпиляция — 20 секундами на функцию.
- Поиск кода ограничен фактически декомпилированными функциями. Лимиты экспорта: 100 тыс. функций, 2 млн инструкций, 500 тыс. констант и ссылок каждого типа; ограничения отмечены в summary.txt. Сырые строки — до 100 тыс. строк или 20 МиБ каждого типа.
- Граф вызовов представлен таблицей рёбер, а не интерактивным GUI. Не все косвенные переходы разрешаются статически. Отдельный контрольный stripped ELF с 256 функциями, доступными через таблицу указателей, выявил только 9 функций при стандартном автоанализе ([журнал](https://github.com/drdroid78/Ghidra-Cloud/actions/runs/45961832664)); это исходное ограничение обнаружения. Добавлен дополнительный поиск таблиц из трёх и более выровненных указателей на исполняемую память, с отчётом pointer-tables.tsv. Это эвристика, возможны ложные кандидаты; найденные адреса не доказывают фактический вызов конкретной функцией. Сканирование ограничено 16 МиБ данных и 4096 новых функций, RAW импорт не использует эту эвристику. Не считать список автоматически найденных функций исчерпывающим.
- Сравнение: точное побайтовое сравнение по одинаковым файловым смещениям и сопоставление отпечатков инструкций по уникальному имени или эвристике адресов. Этот дополнительный байтовый отчёт не является Version Tracking; штатные результаты сохраняются отдельно. вставки и перемещения, релокации, оптимизации могут влиять на результат. Несопоставленная функция не доказательство добавления или удаления.
- Ghidra запускается на временных runner, workflow постоянен. Нет круглосуточного сервера. Стандартные вычислительные минуты публичного репозитория бесплатны в пределах правил GitHub; ограничения длительности и хранения сохраняются.
- [Официальное руководство Headless](https://github.com/NationalSecurityAgency/ghidra/blob/Ghidra_12.2_build/Ghidra/RuntimeScripts/support/analyzeHeadlessREADME.md).
